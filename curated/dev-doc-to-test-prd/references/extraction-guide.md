# 提取指南

## 从PRD中提取什么

PRD是开发视角的技术设计文档，测试需求文档需要从中提取业务规则相关的信息，跳过纯技术实现细节。

### 需要提取的

| PRD内容 | 提取方式 | 对应文档层 |
|---------|----------|-----------|
| 功能目标/背景 | 翻译成一句话用户目标 | 功能概述 |
| 条件判断逻辑（if/校验） | 翻译成"什么条件下能做什么" | 业务规则-前置条件 |
| 执行逻辑（Handler/Service） | 翻译成"做完后结果是什么" | 业务规则-执行规则 |
| 枚举值定义 | 直接复用，补充中文说明 | 业务规则+状态流转 |
| 状态变更逻辑 | 翻译成状态流程图 | 状态流转 |
| 数据库表/字段变更 | 翻译成"变更前后对比" | 数据影响 |
| 异常处理代码 | 翻译成"如果……会怎样" | 异常与边界 |
| 边界值（数量限制、长度限制） | 翻译成极限场景 | 异常与边界 |
| UI截图/原型图描述 | 提取控件类型、联动关系 | 页面交互（🚧占位，待用户补充） |

### 不需要提取的

| PRD内容 | 原因 |
|---------|------|
| Java类名/包名/方法名 | 测试不关心代码结构 |
| 设计模式说明（策略模式、责任链等） | 属于实现细节 |
| MyBatis拦截器原理 | 属于实现细节 |
| SQL语句 | 测试关心结果不关心SQL |
| 部署架构图 | 与功能测试无关 |
| API接口规格 | 功能测试（黑盒测试）不直接测试API接口，接口信息对测试用例设计价值有限 |

## 信息缺口标记规范

| 标记 | 含义 | 使用场景 |
|------|------|----------|
| 🚧 | PRD中没有的信息，需要找开发确认 | PRD信息缺失、截图无法访问、逻辑不完整 |
| 📌 | 基于业务逻辑推断的内容 | PRD未明确说明但可根据上下文推断 |

两种标记必须分开，方便后续对齐时重点确认📌、补充🚧。

## 业务规则编号规范

- BR-01, BR-02, ... ：业务规则
- AB-01, AB-02, ... ：异常与边界场景

编号在同一文档内连续，不按子章节重置。
